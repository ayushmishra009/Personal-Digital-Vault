## Library and validation notes

RustCrypto [`argon2` 0.6.0](https://github.com/RustCrypto/password-hashes/tree/master/argon2) is used by the isolated candidate WASM component and a dedicated Worker provider, but it is not connected to an application flow or approved for real data. Its p=4 exact-tuple primitive output agrees with the recorded independent Go x/crypto v0.37.0 result. p=1 legacy and p=4 proposed vectors pass in Rust-built WASM under Node and Chrome 156.0.8078.81. The standalone native Rust unit-test executable could not run because Windows Application Control blocked it. `Cargo.toml` pins `=0.6.0`; `Cargo.lock` pins registry checksums and the WASM dependency graph excludes optional Rayon parallelism. `cargo-audit` is not installed, so no advisory-database scan was performed.

The proposed `m=2^16 KiB, t=3, p=4, salt=16 bytes, output=32 bytes` tuple matches RFC 9106's second recommended Argon2id option for memory-constrained environments. OWASP Password Storage guidance currently lists a lower minimum of 19 MiB, two iterations, and one lane, and calls for benchmarking the chosen work factor against its target environment. The PDV tuple is a local key-derivation proposal, not a server password-storage setting; browser calibration and independent review remain open. See [RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html) and the [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

Six p=4 Chrome main-thread derivations measured 265.1–288.4 ms (268.8 ms median). Six Worker derivations measured 269.0–350.2 ms (289.2 ms median), with 425 main-thread heartbeat ticks. WASM linear memory measured 68,681,728 bytes in the page harness and 68,354,048 bytes in the Worker. Process RSS, CPU model, and installed RAM were not measured. This is one headless Windows environment, not representative-device coverage. Worker termination cancellation, malformed-input reporting, and responsiveness passed. The crate does not enable RustCrypto's optional parallel feature; p=4 does not mean browser-level threaded WASM.

Envelope tests cover deterministic password/recovery wrapping, p=1 unlock, p=1-to-p=4 rewrap, password changes, wrong passwords/recovery secrets, UTF-8 edge cases, and Worker lifecycle behavior. The fixed envelope fixture matches across Node Web Crypto and Chrome Web Crypto using the actual WASM Worker provider. Native Rust unit-test execution and a two-clean-build reproducibility check were blocked by Windows Application Control in this run. Independent security review and wider browser/device coverage remain required; a reproducible build still needs verification on an environment where Cargo can execute. **PENDING SECURITY REVIEW.**

## Change process

Any protocol deviation requires an explicit decision and corresponding schema, vector, implementation, and test updates. Implementations must reject unsupported values rather than accept arbitrary algorithm strings or silently lower KDF cost.
